# ДомТех — фронтенд

Навчальний проєкт інтернет-магазину побутової техніки (лабораторні роботи, SRS «ДомТех»).
Це фронтенд: односторінковий застосунок на React + TypeScript (DSN-02). Бекенд — окремий репозиторій.

## Що вміє

- **Гість**: каталог із підкатегоріями, фільтри й сортування, пошук, картка товару, кошик (зберігається в браузері).
- **Клієнт**: реєстрація й вхід, оформлення замовлення, кабінет — замовлення, скасування, профіль, зміна пароля.
- **Адміністратор**: замовлення (статуси, оплата), товари, категорії з шаблонами характеристик, виробники,
  клієнти, імпорт прайсу Katran.

## Запуск

Потрібен Node.js 20 LTS або новіший.

```bash
npm install
npm run dev        # http://localhost:5501
npm run build      # перевірка типів (tsc) і збірка в dist/
npm run preview    # перегляд зібраної версії
```

## Без бекенду і з бекендом

Поки бекенду немає, фронт працює на **тимчасових даних (моках)**: каталог, облікові записи, замовлення
й імпорт імітуються в браузері (localStorage). Правила перевірок у моках такі самі, як має робити бекенд.

Щоб працювати зі справжнім сервером, створіть у корені файл `.env.local`:

```
VITE_USE_MOCKS=false
```

Під час `npm run dev` запити на `/api` передаються на `http://localhost:3000` (див. `vite.config.ts`), тож
cookie сесії працює без налаштувань CORS. Інша адреса API — змінна `VITE_API_URL`.

Опис усіх запитів, відповідей і помилок для бекенду — [docs/API.md](docs/API.md).

### Імпорт прайсу

Адмінка → «Імпорт прайсу». Приклад файлу у форматі Katran (CSV, Windows-1251, роздільник `;`) —
[`public/katran-sample.csv`](public/katran-sample.csv); його можна завантажити й зі сторінки імпорту.

Адміністратора створює системний адміністратор службовою командою бекенду (UC-SYS-01) — див. README бекенду.

## Структура

```
src/
  api/          ApiClient, сервіси (інтерфейс + Http… для бекенду + Mock… для моків), моки в api/mock
  components/   спільні компоненти (меню, фільтри, картки, форми, стани списків)
  context/      AuthContext (користувач і сесія), CartContext (кошик)
  hooks/        useAsync, useCategories, useCartCheck та ін.
  pages/        сторінки; account/ — кабінет клієнта, admin/ — адмінка
  styles/       SCSS за BEM: abstracts, base, components, layout
  types/        типи даних, спільні з описом API
  utils/        форматування, підписи, параметри адреси сторінки
  validation/   правила перевірки форм — таблиця 3.5 SRS
docs/API.md     контракт з бекендом
legacy/         початкова статична верстка (HTML/CSS/JS)
```
